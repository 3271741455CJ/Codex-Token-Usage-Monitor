# 中转模型检测的技术与数学原理

**English summary.** Relay Auditor runs reproducible synthetic tasks against a relay and, when configured, a compatible official reference. It separates observed answer quality, response reliability, optional behavioral evidence, and changes in the target’s history. A complete paired comparison uses a one-sided exact McNemar test and a minimum observed effect. Controlled calibration uses frozen scenarios and independent validation seeds. Results are experimental and apply to the sampled tasks and settings. See the [method notes](docs/METHODS.md) and [contribution guide](docs/EXTENDING.md).

## 1. 检测对象与证据范围

工具从客户端观察中转 API 的响应。它测量给定任务、请求配置与采样时间下的表现，包括答题质量、响应可靠性、专项行为分布和历史变化。路由策略、上游模型权重和供应商意图都需要其他证据才能判断。目前发布包没有已完成真实校准的型号。

官方 API 参考是用户单独选择的对照端。配对要求与中转声明匹配的参考型号，以及工具确认可比的请求设置。具体校验覆盖官方预设、请求协议、推理设置、温度、流式选项和输出限制。跨协议配对只在实现明确接受的单轮文本配置下可用。模型目录可见性和生成权限分别验证。无匹配参考时，普通检测仍可单侧运行。响应所报告的型号名属于服务元数据，参考匹配也仅说明请求侧条件。 [参考匹配](relay_auditor/families.py) · [官方适配](relay_auditor/official.py)

## 2. 合成题、确定性评分与缺失处理

一键检测使用 `assessment-v2`。题型由中转声明的模型家族选取，覆盖约束优化、代码追踪、代码纠错、结构化输出、文档规则和虚拟工具参数等。生成器在固定实现、题型、难度和种子下可复现。每题有本地计算的标准答案。请求只携带合成提示，模型响应按 JSON 结构和值评分，生成的代码与虚拟工具参数只作为数据解析。 [任务编排](relay_auditor/assessment.py) · [生成器](relay_auditor/suites.py) · [评分器](relay_auditor/protocol.py)

默认安排 10 题。匹配官方参考时，两侧收到相同题目，计划 20 次生成请求。程序按题交替哪一侧先请求，减少固定请求顺序的影响。每侧分别统计计划、已尝试、已响应、可评分和答对。可评分而未答对的题计为错误。超时、限流、截断、空回答、过滤和 JSON 格式不符合评分要求等进入失败或无法评分计数。无论正确与否，只有双方都有布尔评分的题才进入配对分差。

分母随问题变化。**可评分正确率**是答对数除以可评分数。**配对分差**使用双方都可评分的题。**服务可靠性**用已尝试请求及其响应与失败计数呈现。失效样本可能集中在较难题目，读报告时应把覆盖率与得分一起看。即使有效子集很大，只要有计划中的配对不完整，该批便保留为对照不完整。 [对照代码](relay_auditor/assessment.py) · [报告代码](relay_auditor/reports.py)

运行前按计划请求数和单次保守估算检查本地预算。每次尝试登记后，已知 token 用量按接口返回值结算，缺少用量的尝试保留预留估算。预检估算包含提示字节、输出上限和额外余量，最终账单应以接口提供方的独立证据为准。 [预算预检](relay_auditor/planning.py) · [用量存储](relay_auditor/storage.py)

## 3. 同题分差与单侧精确 McNemar 检验

将同一道题在官方参考和中转上的正确性分别记为 0 或 1。对所有双方可评分的题计数。

| | 中转答对 | 中转答错 |
| --- | ---: | ---: |
| 官方答对 | $a$ | $b$ |
| 官方答错 | $c$ | $d$ |

有效配对数为 $n=a+b+c+d$。官方得分为 $(a+b)/n$，中转得分为 $(a+c)/n$。报告中的中转劣势记为 $Delta=(b-c)/n$。$Delta=0.10$ 表示中转低 10 个百分点。

在成对二元结果符合检验假设时，零假设的边界上，两种相反方向的不一致结果等可能。给定不一致对数 $m=b+c$，统计量 $B$ 按 $operatorname{Binomial}(m,1/2)$ 计算。检验关注中转表现更低的一侧，使用精确尾概率。 [McNemar 的配对比例检验](https://pubmed.ncbi.nlm.nih.gov/20254758/) · [项目的精确计算](relay_auditor/statistics.py)

$$
p=Pr(Bge b)=2^{-m}sum_{k=b}^{m}inom{m}{k}.
$$

两边答得一样的题影响总体分差的分母，但不会增加 $m$。有有效配对而 $m=0$ 时，代码返回 $p=1$。无有效配对时，报告中的 $p$ 为空。

正式标记 `degraded` 同时要求全批配对完整、至少 40 对、$Deltage 0.10$ 且 $plealpha$。完整样本中达到分差门槛而未达到显著性门槛时，返回 `inconclusive`。分差小于门槛时，返回 `no_detected_degradation`。这两个状态的解释都受题量、采样条件与统计功效限制。 [判定规则](relay_auditor/statistics.py)

例如，以下是演算用的两组合成计数。

| $a,b,c,d$ | 观察到的分差 | $p$ | 可给出的说明 |
| --- | ---: | ---: | --- |
| $6,3,1,0$ | 20 个百分点 | 0.3125 | 10 对初筛只报告观察差距 |
| $24,14,2,0$ | 30 个百分点 | 约 0.00209 | 40 对满足首个判定序号的门槛，第二个序号下仍未达到显著性门槛 |

本地数据库按北京时间的日期维护判定序号 $j=1,2,ldots$，分配 $alpha_j=0.01/[j(j+1)]$。前两次分别是 $0.005$ 和约 $0.001667$。由 $1/[j(j+1)]=1/j-1/(j+1)$ 可知单日分配和不超过 $0.01$。只有每个统计检验在其假设下有效时，才可由并集界控制所分配检验的名义误报概率。这一预算公式本身无法给出现场实测误报率。 [日序号存储](relay_auditor/storage.py) · [阈值计算](relay_auditor/statistics.py)

一键检测只有在完整且达到 40 对时才领取正式序号。其他专项审计可以在开始时领取序号。10 题初筛在完整配对、观察差距达到 10 个百分点且目标、型号、协议、参考仍匹配时，可以进入用户确认的复核。复核生成 40 至 200 对新题，题目种子区间与初筛不重叠。初筛和复核分别展示。 [复核绑定](relay_auditor/controller.py)

### Wilson 区间

报告对可评分正确率展示 95% Wilson 分数区间。设成功数为 $x$、所用分母为 $n>0$、$hat p=x/n$，取 $zapprox1.96$。区间中心和半宽如下，端点约束在 $[0,1]$。 [Wilson 原论文](https://jhanley.biostat.mcgill.ca/c607/ch08/wilson_jasa_1927.pdf) · [报告实现](relay_auditor/reports.py)

$$
C=rac{hat p+z^2/(2n)}{1+z^2/n},qquad
R=rac{z}{1+z^2/n}sqrt{rac{hat p(1-hat p)}{n}+rac{z^2}{4n^2}}.
$$

这里的区间描述单个比例的抽样不确定性。配对差距需保留配对信息。报告生成器在完整配对的 `no_detected_degradation` 状态下，还检查「仅官方答对」比例 $b/n$ 的 Wilson 上界，只有上界不超过 10% 才产生「本轮未发现明显能力差距」的保守说明。跨任务与模型版本的等效性需要专门设计与验证。

## 4. 可选的行为审计与历史信号

普通 `assessment-v2` 不生成行为指纹。行为审计在同一场次向两端发送硬币、数字、骰子、颜色和星期五类短提示。每类独立统计答案类别，已收到但无法归类的响应进入 `OTHER`，请求失败单列。网络失败或每类样本少于 20 时，行为审计报告证据不足。 [分类器](relay_auditor/protocol.py) · [审计流程](relay_auditor/controller.py)

对每类探针，两侧的经验分布分别为 $P$ 与 $Q$，取 $M=(P+Q)/2$，以 2 为对数底。统计量为各探针类别的 Jensen–Shannon 散度均值。

$$
operatorname{JSD}(P,Q)=	frac12 D_{mathrm{KL}}(Pparallel M)+	frac12 D_{mathrm{KL}}(Qparallel M).
$$

置换检验在每类探针内部打乱端点标签、保持两组样本数。进行 $B$ 次置换，$e$ 次取得至少与原观测同样极端的统计量，估计 $p=(e+1)/(B+1)$。当最小分辨率 $1/(B+1)$ 已超过分配的 $alpha$ 时，报告分辨率不足。检验所需的交换性可能受到缓存、统一模板、限流、时间漂移和请求相关性的影响。分布差异可供专项复核，归因仍需独立证据。 [Lin 的散度论文](https://doi.org/10.1109/18.61115) · [置换实现](relay_auditor/statistics.py)

**旧版序列指纹**用一条包含 315 个指定范围整数的完整响应作为一个观测。边际直方图 355 维、四段的有序位置统计 $4	imes16$ 维和个位数 10 维组成 429 维特征。每组计数加 0.5 后归一化并取平方根。旧版以匹配参考的特征均值为中心，使用加权距离。少于 12 条有效参考响应或基线超过 7 天时，证据不足或过期。可比较时的阈值为 $max(0.08,1.25D_{max})$，其中 $D_{max}$ 是基线样本离中心的最大距离。这是启发式偏离规则。导入的数字参考包保留用户历史来源，可信度与官方同期参考分开。 [特征实现](relay_auditor/protocol.py) · [旧版筛查](relay_auditor/controller.py) · [参考包](relay_auditor/reference.py)

**历史变化**只比较同目标、同模型、同协议、同题库版本、同模式、同参考绑定与同样本数的可比记录。新版从近期完整记录中取最近四个不同种子，两轮近期成绩都比两轮较早成绩低至少 10 个百分点时才给出下降线索。这个规则是用户自己的历史对照。不同任务、端点、时间或协议的数据不宜直接排名。 [趋势实现](relay_auditor/reports.py)

## 5. 真实校准与统计验收

源码校准工具在采样前冻结关键代码的 SHA-256、主型号、替代型号、协议设置、种子、场景、判定序号、样本量和验收门槛。当前工具的真实采样端点限定为指定的 OpenAI 官方 API，覆盖受支持的 GPT/Codex 型号。能力评估场景复用桌面 `assessment-v2` 的出题、评分与判定。研究固定某个 $alpha_j$，默认 $j=1$。不同日序号、家族、接口或题库需要各自的证据。 [校准实现](relay_auditor/calibration.py) · [命令说明](docs/METHODS.md)

| 场景 | 对照设置 |
| --- | --- |
| 正常 `healthy` | 两侧均使用主型号与相同协议 |
| 完整替换 `substitution` | 参考侧为主型号，测试侧每次使用指定替代型号 |
| 推理档位变化 `reasoning_changed` | 扩展场景。测试侧请求指定较低档位 |
| 上下文截断 `context_truncated` | 扩展场景。用单独标记的 `context-v1` 截断控制 |
| 混合路由 `mixed_10` / `mixed_30` / `mixed_50` | 扩展场景。按冻结概率及随机种子切换测试侧型号 |

每场景有 10 次先导。正式验证使用与先导不重叠的种子，并且采集日须晚于所有先导日。先导可按题型和难度汇总，用于发现区分度不足或格式问题。调整任务或阈值后，重新冻结方案再做正式验证。报告保留无法判定的试验、请求次数与可结算用量，按配对计数复算判定。模拟混合比只描述实验所施加的路由比例。

验收看的是整轮检测的误报与检出能力。对 $N$ 次正式试验中的 $x$ 次计数事件，使用双侧 95% Clopper–Pearson 精确二项区间，通过反演二项尾概率求上下界。对正常控制，未决试验并入误报上界的保守分子。对完整替换，未决试验按未检出保留在分母中。验收候选须完成冻结场景的全部试验，并满足**正常误报率的区间上界不超过 5%**，以及**完整替换检出率的区间下界不低于 80%**。这些区间仍依赖试验独立等条件。 [Clopper–Pearson 原论文](https://doi.org/10.2307/2331986) · [验收实现](relay_auditor/calibration.py)

例如，100 次正常试验全部可判定且 0 次误报时，上界约为 3.62%。这些是公式演算值。工具把统计达标记为待人工复核的候选，复核应检查盲测隔离、控制条件、精确型号版本、样本相关性、失败记录与可复现性。

## 6. 社区改进与本地复现

- **提高题型区分度。** 在正常、替代、边界推理档位和混合路由条件下分别记录每类任务的完整率与配对分差。用先导数据筛题，冻结后用独立验证数据估计功效。
- **改善缺失诊断。** 区分无响应、流中断、截断、拒答、格式不符合约定和可评分的错误。任何改变缺失处理或统计分母的方案都应保留原始汇总分母并重新校准。
- **减少请求相关性。** 在时间、模型版本、协议和输入长度条件内安排对照。发布不同请求预算下的可判定率、误报与检出区间。评估缓存、响应复用和上游漂移的影响。
- **守住贡献边界。** 修改生成器、评分、采样分布或协议语义时更新相应版本。示例用合成题、模拟客户端与匿名统计。代码审阅聚焦固定授权端点、预算、取消行为和数据脱敏。
